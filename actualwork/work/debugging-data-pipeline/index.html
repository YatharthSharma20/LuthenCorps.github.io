Debugging a Broken Data Pipeline at 2 AM

Priya MenonData EngineerTechnology3 years experience

Loading video…

The Objective

A nightly ETL pipeline that feeds the analytics dashboard failed silently. The dashboard was showing stale data from two days ago, and the sales team had a board meeting in the morning.

What Happened

Priya walks through how she debugged a broken data pipeline — tracing the failure from the dashboard back through the orchestration layer, finding a schema change in an upstream API that broke the ingestion step, and deploying a fix before the morning meeting.

The Actual Work

  1. Got an alert at 2 AM that the dashboard data hadn't refreshed.
  2. Checked the Airflow DAG — the ingestion task had failed but the DAG itself showed 'success' because of a misconfigured retry policy.
  3. Looked at the ingestion logs. Found a JSON parsing error: a field that used to be a string was now an array.
  4. Checked the upstream API changelog — they had pushed a breaking change without versioning.
  5. Wrote a quick schema migration to handle both the old and new format.
  6. Tested locally against a sample of the new API response.
  7. Deployed the fix and triggered a manual backfill for the missing days.
  8. Added a schema validation check at the ingestion step so this type of silent failure would be caught immediately in the future.

Conclusion

Dashboard was showing fresh data by 5 AM. Added schema validation that has since caught three similar issues before they reached production.
